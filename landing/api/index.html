Empezar

La API deja que el sistema de tu negocio (tu tienda en línea, tu programa de socios, tu sistema de cobros) hable con tu cuenta de Sobreala sin entrar al panel: carga y actualiza contactos, usa tus plantillas y tus remitentes, envía correos y lee lo que pasó con ellos.

Todas las direcciones empiezan por https://app.sobreala.com/api/v1. Se habla en JSON y en UTF-8, y siempre por HTTPS.

Lo primero es crear una llave en el panel: Dashboard → API → Llaves. Con ella, esta llamada dice de quién es la cuenta y si hoy se puede enviar:

curl https://app.sobreala.com/api/v1/me \
  -H "Authorization: Bearer sa_live_tu_llave"

La llave

Cada petición lleva la llave en la cabecera Authorization: Bearer. Nunca en la dirección: una llave que llega ahí se rechaza y se revoca sola, porque queda escrita en los registros de los servidores por donde pasa.

La llave va en tu servidor, nunca en una página web, en una aplicación que se descarga ni en un repositorio. La API no acepta llamadas desde un navegador de otra página.

La llave se ve una sola vez, al crearla: nosotros guardamos solo una huella de ella. Si la pierdes, crea otra y revoca la vieja. Cada llave puede vencer, y puede quedar limitada a unas IP.

Crear una llave pide tu contraseña (o un código a tu correo) y el código de tu app si tienes segundo factor, y te llega un correo cada vez que se crea o se revoca una.

Permisos

Cada llave tiene los permisos que le diste al crearla, y cada ruta dice cuál pide. GET /me y GET /senders responden a cualquier llave.

Llaves de prueba

Una llave que empieza por sa_test_ es para ensayar: lee todo lo que sus permisos dejen, y los envíos se simulan. POST /emails arma el correo, lo revisa y te lo devuelve armado, pero no sale nada, no se gasta cuota y no se guarda nada. Enviar o programar una campaña dice a cuántos saldría y qué la frena, sin cambiar nada.

Una llave de prueba no puede escribir: ni crear contactos ni plantillas ni campañas. Así, si se filtra desde un servidor de pruebas, no puede tocar tu lista. Para escribir hace falta una llave de verdad (sa_live_).

Errores

Un error responde con su estado HTTP y un cuerpo como este. code es para tu programa y message para leerlo; fields aparece cuando hay campos que no están bien, y request_id es lo que nos dices si nos escribes.

{
  "error": {
    "code": "validation_failed",
    "message": "Hay campos que no están bien: los dice fields.",
    "fields": {"subject": "Falta este campo."},
    "request_id": "req_3f9a2c1b7d4e8a60"
  }
}

unauthorized401Falta la llave, o no es válida, está vencida o se revocó.
key_in_url400La llave llegó en la dirección. Se rechaza y, si era buena, se revoca: ahí queda escrita en registros ajenos.
ip_not_allowed403La llave tiene una lista de IP y esta no está.
account_suspended403La cuenta está suspendida.
account_closed403La cuenta todavía no se abrió (falta la demostración o un plan).
test_key_cannot403Una llave de prueba no puede hacer esto: solo lee y simula envíos.
missing_scope403La llave no tiene el permiso que pide esta ruta.
rate_limited429Demasiadas peticiones. Espera lo que dice Retry-After.
not_found404No existe, o no es de esta cuenta. Las dos cosas responden igual.
method_not_allowed405La ruta no acepta ese método.
too_large413La petición pasa del tamaño permitido.
unsupported_media_type415El cuerpo no es JSON (o multipart donde se sube un archivo).
bad_json400El cuerpo no es un objeto JSON válido.
validation_failed422Hay campos que no están bien; fields dice cuáles y por qué.
bad_cursor400El cursor no salió de una respuesta anterior.
bad_idempotency_key400La Idempotency-Key no tiene la forma pedida.
idempotency_mismatch422Esa Idempotency-Key ya se usó con otro cuerpo.
idempotency_busy409La primera petición con esa Idempotency-Key sigue en curso.
busy409Ya hay una carga de contactos en curso en la cuenta (por la API o una importación del panel). Reintenta en unos segundos.
unknown_tag422Hay etiquetas que no existen; tags dice cuáles. Se crean antes con POST /tags.
email_taken409Esa dirección ya la tiene otro contacto de la cuenta.
tag_exists409Esa etiqueta ya existe.
limit_reached409Se llegó al tope de tu plan (etiquetas, columnas, plantillas, carpetas o fotos).
field_exists409Ya hay una columna con esa clave, o es Nombre o Correo, que todo contacto ya trae.
field_values409Hay contactos con valores que no encajan en el tipo nuevo; contacts dice cuántos.

internal_error500Algo falló de nuestro lado. Escríbenos con el request_id.

Límites

Por cuenta, sumando todas sus llaves: 600 peticiones por minuto. Además, por minuto: 120 correos, 30 cargas de contactos (y 5,000 filas), 5 plantillas o ZIP, 20 fotos y 30 consultas de estadísticas. Pasado un límite responde 429 con la cabecera Retry-After, en segundos.

El cuerpo de una petición llega hasta 1 MB, y hasta 6 MB el ZIP de una plantilla y una foto. Lo pesado va de uno en uno por cuenta: dos cargas de contactos a la vez no se cruzan.

Los correos gastan la cuota de tu plan, como en el panel. En la demostración solo salen a tus direcciones de prueba.

Listas largas

Las rutas que devuelven listas aceptan limit (de 1 a 100, 25 si no se dice) y responden data y next_cursor. Para la página siguiente se pide la misma ruta con cursor igual a ese next_cursor; cuando viene null, no hay más.

{
  "data": [ ... ],
  "next_cursor": "ZS1h9Xc2bm9wcXJz"
}

Reintentar sin repetir

Si la red se corta y no sabes si un envío salió, reintenta con la misma cabecera Idempotency-Key (hasta 100 caracteres sin espacios, por ejemplo un id de tu pedido). La segunda vez recibes la respuesta de la primera, con la cabecera Idempotent-Replayed: true, en vez de mandarlo otra vez.

La aceptan POST /emails, POST /contacts, POST /campaigns y enviar y programar una campaña. Se guarda 24 horas, para esa llave y esa ruta. Con otro cuerpo responde 422; mientras la primera sigue en curso, 409.

Fechas y horas

Las fechas salen en UTC, como 2026-10-20T20:00:00Z. Las que mandas van en ISO 8601 con su zona: 2026-10-20T15:00:00-05:00 son las tres de la tarde en Panamá. Una sin zona se rechaza, porque no se sabe de dónde es.

Lo que la API no hace

Hay cosas que se hacen solo en el panel, porque son de una persona y no de un sistema: la contraseña y el segundo factor, los usuarios, pagar y cambiar de plan, conectar dominios y confirmar remitentes, crear llaves y avisos, y eliminar la cuenta.

POST /contacts

Cargar contactos

De 1 a 1,000 por vez. Los nuevos entran si caben en tu plan y traen todas tus columnas; los que ya están se actualizan (las etiquetas se suman, nunca se quitan). Cada fila dice qué le pasó en results, en el orden en que llegó: added, updated o rejected con su motivo (invalid_email, duplicate, unknown_tag, unknown_field, bad_value, incomplete, limit). Una dirección dada de baja se guarda pero no recibe (warning: suppressed), y una de un dominio que no recibe correo entra marcada (warning: undeliverable). Hasta 5,000 filas por minuto.

Permiso: contacts:write · Con una llave de prueba: no.

En el cuerpo

contacts obligatorio
lista		 Cada uno con email, y si quieres name, tags (etiquetas que ya existen) y fields (tus columnas por su clave).
consent obligatorio
objeto		 De dónde salieron: source es own_form (tu formulario), members (socios), customers (clientes), event (un evento) u other; note, hasta 300 caracteres. Se guarda en cada contacto nuevo, y es lo que enseñas si alguien reclama.
tags
lista de textos		 Etiquetas para todos los de esta carga.

Pedido

curl -X POST https://app.sobreala.com/api/v1/contacts \
  -H "Authorization: Bearer sa_live_tu_llave" \
  -H "Content-Type: application/json" \
  -d '{
  "consent": {
    "source": "customers",
    "note": "Clientes de la tienda"
  },
  "tags": [
    "Clientes"
  ],
  "contacts": [
    {
      "email": "ana@ejemplo.com",
      "name": "Ana Pérez",
      "fields": {
        "CIUDAD": "Santiago"
      }
    },
    {
      "email": "luis@ejemplo",
      "name": "Luis"
    }
  ]
}'

Respuesta 200

{
  "added": 1,
  "updated": 0,
  "rejected": 1,
  "results": [
    {
      "index": 0,
      "email": "ana@ejemplo.com",
      "result": "added"
    },
    {
      "index": 1,
      "email": "luis@ejemplo",
      "result": "rejected",
      "reason": "invalid_email"
    }
  ]
